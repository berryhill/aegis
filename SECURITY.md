# Security Policy

## Status and supported versions

Aegis is pre-1.0 MVP software and is not supported for production use. Security fixes are applied to the current `main` branch and are included in subsequent stable releases; older published `0.1.x` releases do not receive backports. The latest published release must not be interpreted as a production-support commitment.

## Reporting a vulnerability

Do not disclose suspected vulnerabilities in a public issue, discussion, pull request, recording, or chat log. Use GitHub private vulnerability reporting from this repository's **Security** tab when it is enabled. If that facility is unavailable, stop before sending exploit details or secrets: the repository owner must publish a private security contact. That owner decision is an unresolved launch blocker; this project does not invent a contact address.

Include the affected revision, impact, prerequisites, a minimal reproduction, and whether credentials or third-party systems may have been exposed. Never include live credentials.

## Response process

A maintainer should acknowledge a private report, reproduce and classify it, coordinate a fix and regression test, prepare an advisory, and agree on disclosure timing with the reporter. Response-time commitments will be published only after maintainers establish a staffed reporting route.

## Current security boundaries

New local-gateway onboarding keeps reusable API transport material in an absolute, current-owner, mode-`0600`, single-link `api.token_file`; explicit development and production transport reconciliation generates 256 random bits and never renders the value in its preview, the systemd unit, argv, or environment. The same reconciliation publishes the absolute Unix-socket path only after fresh configured-principal verification, exact original/result configuration digests, and conventional `[Y/n]` confirmation. Aegis then offers one deterministic `systemd --user` gateway unit only after a separate `[Y/n]` principal confirmation. Both prompts accept only case-insensitive Enter, `y`, or `yes`; every other answer, EOF, cancellation, or input failure declines without mutation. Exact complete-plan and artifact revalidation immediately before mutation, not copied prose, remains authoritative. Activation has explicit publish, daemon-reload, enable/start, exact loaded-fragment validation, and authenticated audit-current readiness phases; phase-tagged failures retain readiness and rollback evidence. Rollback removes only newly published bytes and reverses only gateway state introduced by that apply, preserving a pre-existing exact unit and its active/enabled state. Start/stop/restart likewise validate the exact current Aegis-owned unit before invoking `systemctl`; absence returns `gateway_not_installed` with the exact `aegis gateway install` remediation and no mutation. After the action they require the loaded fragment to remain the approved path and wait for observed active/inactive state; start and restart also require authenticated audit-current readiness. Only a pending, nonzero, verifiable audit projection may be advanced through the protected bounded principal audit-delivery endpoint; authorization denial, terminal or unverifiable audit state, and timeout remain failures. Aegis never enables linger, installs a root/system service, or overwrites a foreign or byte-drifted unit. The unit runs under the principal's same account and is only a supervision/single-online-owner boundary: it is not isolation from another same-UID process, root, or the kernel, and `NoNewPrivileges=true` is not a sandbox.

The serving daemon acquires an owner-only, current-owner, single-link nonblocking lock at `<api.unix_socket>.lock` before inspecting or removing an existing owned socket. Concurrent startup denies before socket mutation. While that Unix socket exists, store-backed CLI construction denies with `control_plane_online`; there is no direct-store fallback, so the daemon remains the sole online owner of authoritative stores. `aegis console` is the implemented non-launching daemon client for browser onboarding: it reads protected token custody locally, uses authenticated Unix transport, and returns only a short-lived single-use bootstrap and origin. `aegis manager` and the healthy-startup `terminal` action use the same protected transport to obtain a short-lived in-memory manager session bound to the authenticated principal and exactly one `secrets-manager` stanza. Every typed slash request repeats transport authentication and session authorization before the daemon's sole application service executes it; the client never opens gateway-owned persistence or falls back to direct state. Missing, expired, revoked, or interrupted authentication denies and requires a fresh invocation. Before inspecting or opening operational authority, bare development and production startup verify exact installed unit bytes, the loaded systemd fragment, the loaded `ExecStart` executable and complete `serve --config` argv, activity, and authenticated audit-current readiness. Healthy ownership presents explicit console/terminal/exit routing with default exit; console may mint and launch a single-use browser bootstrap, while terminal launches the authenticated gateway client without opening a second store writer. Mismatched or unhealthy gateways and dirty or corrupt closed authority deny before bootstrap reconciliation. The browser command receives the configured `/console` URL as one direct argument; it is never shell-interpreted and does not embed the bootstrap. Bootstrap denial prevents browser invocation; launcher failure returns a manual URL and the still-short-lived bootstrap. Neither client path establishes durable authority, persists browser or manager credentials, or creates a broadly authorized Hermes gateway.

Aegis authenticates the configured local principal from OS identity, or Linux Unix-socket callers from `SO_PEERCRED`. Identity and authority are established outside the model: prompts, profile or stanza names, model conclusions, bearer tokens, and requested stanzas are not authentication. Each operational session binds to exactly one authorized trust stanza; zero matches and multiple matches deny, and authority is never unioned across stanzas. A stanza or material-authority change requires a new mandate and clean session. Bearer tokens authenticate API transport only. Plan creation requires the configured principal and exact local environment. One immutable plan ID plus exact charter and plan digests, runtime, and environment bind each single-use approval; those bindings are revalidated at request, decision, apply, and interrupted-provisioning recovery. Operational sessions use fresh Hermes processes and disposable homes, and receive only explicitly resolved environment-backed provider credentials and toolset launch arguments.

The embedded browser console does not authenticate a principal from browser input, a display name, a cookie, or bearer possession. An existing principal authenticated through the protected API transport may mint one random single-use bootstrap whose lifetime is at most 60 seconds and never exceeds the source subject's expiry. Exact-origin exchange creates only an in-memory browser transport session, capped at 15 minutes and at the same subject expiry. The cookie is `HttpOnly`, `SameSite=Strict`, scoped to `/console`, and `Secure` under HTTPS; no reusable API bearer is rendered into HTML, URLs, logs, client-visible data, or browser storage. Mutations require the exact configured origin and a session-bound CSRF value. Console responses are rendered from typed Go values through generated templ components and use native same-origin forms and links, so authentication, navigation, inspection, close, and sign-out do not depend on executable client JavaScript. The retained pinned Datastar asset remains self-hosted from the embedded executable and its digest and provenance remain checked in CI/release verification, but the console document does not load it. No CDN or inline executable content is permitted. Responses are no-store and carry a restrictive CSP, frame denial, MIME-sniffing denial, referrer and permissions restrictions, and same-origin opener/resource policy. Plain HTTP is rejected unless both the console origin and TCP listener are loopback; remote deployments require TLS. Browser sessions are volatile and disappear on restart. They are transport sessions, not mandates, runtime sessions, trust stanzas, or durable authority.

The optional local credential authority encrypts each immutable value before bbolt persistence with a fresh XChaCha20-Poly1305 DEK and wraps each DEK under a versioned KEK held outside the database. Bare onboarding generates that KEK and persists only an XChaCha20-Poly1305 envelope under an Argon2id-derived passphrase key. Authority-passphrase creation and unlock are pinentry-first, use bounded Assuan-style pipes and a minimal desktop/session environment, and fall back only before protected interaction to terminal-backed no-echo intake; the passphrase is not persisted. Cancellation and post-interaction failures never downgrade to a second input surface. This provides protected routing and offline encrypted-file protection, not protection against root, a compromised account/desktop session/pinentry executable/terminal, an active process, the kernel, Go memory copies, or passphrase guessing. Pinentry is not GPG-agent integration, a desktop keyring, hardware custody, or a cache. Administrative CLI operations require the configured OS principal, return metadata only, enforce strict file ownership/modes and exact deployment bindings, and emit metadata-only audit events. On Linux, the optional broker adds one typed `github.get_repository.v1` operation over a pathname socket. It combines pre-body `SO_PEERCRED`, a session-bound capability, current mandate/charter/runtime identity, exact `github/read` binding and `github-api` destination, then applies the value internally and returns a sanitized field allowlist. It has no GetSecret or generic proxy endpoint. See `docs/CREDENTIAL_BROKER.md`.

These controls are not a host filesystem, network, container, or VM sandbox. bbolt does not provide encryption or RBAC, Go does not guarantee plaintext-memory zeroization, logical revocation does not erase backups/free pages, and local root can inspect usable plaintext. The broker requires distinct production service/runtime identities. Its sole model-visible bridge is generated in a disposable Hermes home and launch fails unless the live gateway reports exactly the one typed GitHub metadata tool; this is not network confinement and does not make other credentials brokered. Selective deployment projections remain unimplemented; Hermes still uses environment-backed provider bindings. Hermes profiles and homes isolate runtime state, not host authority. Ordinary toolset launch-argument verification is not individual-tool runtime attestation. Local audit records are hash-linked and have signed checkpoints. Their metadata-only outbox and local canonical-order projection provide restart-safe bounded delivery, aggregate readiness, and rebuildable derived state, but they are not an external sink or independent tamper boundary. Canonical audit is not externally tamper-proof unless checkpoint retention and append authority are deployed across separately protected boundaries. See `docs/THREAT_MODEL.md`.

The Agent Registry accepts only strictly validated current-fleet fixture proposals and immutable, content-digested registrations and revisions. A source record, capability declaration, lifecycle value, or successful exact lookup is not authentication, stanza selection, a mandate, or runtime admission. Exact registration replay is idempotent; source/Agent conflicts, revision overwrite or gaps, digest substitution, post-retirement publication, and execution resolution of disabled or retired revisions deny. The adapter does not scan ambient profiles, environment variables, credentials, dashboards, or legacy handoff stores. Principal-authenticated public CLI/API registration and reads now use the durable Badger fleet repository through shared application services; transport identity and fresh authority admission remain separate gates, and Registry records never grant runtime authority.

Runtime authority is split across bounded canonical records. A mandate is an authorization grant, while one immutable authority context binds exactly one session to the mandate, effective authority, charter revision, and explicit runtime. The internal canonical authority codec restricts lifecycle intent to closed activate/revoke/expire commands with an authenticated actor, half-open acceptance window, and exact chain preconditions. The Badger authority repository accepts a command only by atomically writing its immutable controller-authored fact, durable receipt, current projection, and derived outbox entry. Exact retries return the replay-verified receipt without duplicate work; a reused command ID with a different digest denies; transaction failure leaves no partial command result. Current projection and admission reads replay canonical command/fact history and compare stored derived state in one read transaction. Only after those checks may the repository derive an immutable committed-authority position binding context, sequence, fact digest, and projection digest. Canonical audit delivery consumes the verified authority outbox in strict sequence and creates metadata-only evidence for that exact position; gaps, reordered or substituted records, and malformed evidence fail closed. The grant-producing readiness read denies until evidence reaches the current committed position in the same Badger snapshot. Receipts, projections, outbox entries, and audit evidence remain non-authoritative and cannot grant authority. This processing boundary is not yet a CLI/API mutation workflow or fully integrated into existing application launch paths. Content-addressed runtime artifacts and verification receipts are separate evidence only and do not grant authority or declare workflow success. The verifier remains a same-process component using the same local store and account, not independent attestation or separately protected evidence custody. The former experimental plumbing/GraphRun CLI and API proof surfaces have been removed.

The Loop domain is definition and validation substrate only. It uses immutable typed revisions, deterministic canonical digests, strict bounded decoding, and fail-closed structural validation; publication records bind an exact validator result. The fleet repository durably commits an immutable Loop revision, its exact validation, exact-request idempotency binding, and repository-assigned audit fact atomically. Changed validation or audit semantics under the same key deny. Public CLI/API publication uses the shared application service and requires a principal-authenticated subject plus one freshly admitted exact authority context; contextual readiness is not a grant. These records do not authenticate a publisher, select a stanza, issue a mandate, launch Hermes, or prove execution success. Lifecycle selection and general Graph execution remain unimplemented.

The Graph domain is also definition and validation substrate only. Its immutable revisions bind exact Agent and Loop revision/digest references, typed acyclic dependencies and port mappings, exact policy digests, and validator identity. Strict bounded codecs and deterministic digests reject malformed, duplicate, trailing, substituted, cyclic, incomplete, or type-incompatible structures. Public CLI/API Graph publication and submission use the shared application service, require an authenticated principal and freshly admitted exact authority context, verify the publishing Agent is an exact participant, and turn admission failures into bounded durable rejections where possible. Accepted submission resolves the exact stored Graph, valid Graph and Loop validations, every enabled Agent revision, every Loop revision, and the snapshot-derived reference set in the same transaction that publishes the run snapshot, submission, queue item, initial Graph run, queued transition, projection, idempotency binding, and audit fact. Rejected submission publishes one immutable negative outcome and audit fact under the same idempotency namespace. Conflicting outcomes deny and failed transactions leave no partial lifecycle or audit fact. This does not select Graph/Loop lifecycle, launch Hermes, or establish success. The narrow no-key worker performs fresh claim, runtime-effect, evidence-verification, and successful-disposition admission and commits one terminal outcome; durable reclaim/retry/cancellation primitives exist, but automated lifecycle scheduling, multi-node scheduling, and real Hermes worker integration remain absent.

`internal/queue`, `internal/execution`, `internal/evidence`, and `internal/disposition` remain bounded domain records rather than sources of authority. Public CLI/API queue submission, exact readback, and explicit processing call one narrow controller-side worker that supports only an exact single-node Graph with one executable action. It performs fresh controller admission before claim and runtime effect, uses a deterministic no-key adapter or injected runtime port, stores output by content digest, repeats admission before each evidence verification and successful disposition, and atomically publishes evidence metadata, one terminal disposition, the queue transition, projection, and repository-assigned audit. Runtime bytes and adapter errors are untrusted; invalid output, failed verification, or admission denial cannot become success. Claims require available canonical timing, remaining attempt capacity, and exact succeeded dependencies; expired leases can be reclaimed through bounded backoff, queued or claimed work can be cancelled, and completion requires the matching unexpired active claim. Each mutation atomically updates canonical facts, active-claim binding, projection, and audit. A claim remains only a bounded lease fact and artifacts, receipts, projections, and dispositions cannot authenticate a worker or grant authority. The release-shaped installed verifier exercises the exact initial no-key path, but automated lifecycle scheduling, dirty-store recovery, multi-node scheduling, and a real Hermes-backed worker adapter remain absent.

Generation-changing Badger maintenance is coordinated across cooperating Aegis processes with a root-scoped no-follow mode-`0600` `flock`. Open stores hold shared leases; initialization, export, import, activation, rollback, recovery, projection rebuild, and garbage collection require the applicable closed-clean and context-cancellable maintenance boundary. Qualified Linux marker writes/removals, generation moves, failed-staging cleanup, and garbage-collection deletion use no-follow descriptor-relative operations; GC also revalidates the captured device/inode before deletion. Candidate-producing operations check that their bounded output plus a fixed 256 MiB reserve is available before mutation. Export is bounded and non-replacing. Logical recovery imports only verified canonical records into a fresh inactive identity and rebuilds derived authority projections from canonical replay; native recovery requires an exact retained generation. Activation, rollback, and native recovery report whether selection was durably committed even if retirement cleanup or a later sync fails, so callers cannot misclassify a selected generation as wholly unapplied. Garbage collection refuses malformed, unknown, ambiguous, substituted, or active generations. The backup payload SHA-256 is an integrity check only: authority backups are not encrypted or cryptographically signed and do not independently authenticate their publisher or prevent whole-host rollback. Descriptor anchoring and the coordinator are not a sandbox and do not protect against root, the kernel, denial of service, or malicious same-account mutation of already-open file contents.

Storage qualification is fail-closed and deliberately narrower than artifact portability. The reviewed post-Track-A combinations are Badger `v4.9.5` for session authority plus the separate fleet-definition and fleet-lifecycle planes, and bbolt `v1.5.0` for credential custody, only on Linux/amd64/ext4 under one Aegis process. The fleet planes share schema `fleet-v1` at the exact `state/persistence/fleet-v1` root and require the exclusive writer lock, restrictive modes, a 256 MiB reserve, completed migration state, and clean or verified-recovered lifecycle evidence before readiness. Any changed engine version, platform, filesystem, writer model, path, schema, lifecycle, or durability dimension requires explicit requalification. The adapter implements atomic accepted-or-rejected submission persistence, dependency-gated attempt-bounded claims, expired-lease retry/reclaim, queued-or-claimed cancellation, validated rebuildable projections, and atomic terminal evidence/disposition persistence. Public wiring and installed no-key proof exercise fresh admission through the narrow initial execution path, but do not complete migration/backup/recovery, dirty-store recovery, automated lifecycle scheduling, or real Hermes integration. Cross-built macOS/arm64 archives and the native installed proof do not establish persistence safety outside the qualified envelope. Ordinary canonical documents, projections, blobs, operational metadata, runtime state, and credential custody are separate planes, and no projection, lifecycle marker, runtime home, audit-delivery marker, or cross-store partial result may substitute for canonical authority. See `specs/STORAGE.md`.

The built-in manager owns terminal input, rejects bare non-terminal invocation, scans bounded source-aware content, strictly decodes one closed response/proposal envelope, and routes ordinary conversation through a one-use-per-turn gate and an exact-model loopback proxy bound to the launched Hermes process. Hermes receives only a fixed public API-key-shaped parser-compatibility string; it grants no proxy authority. On Linux, Aegis starts a pipe-blocked child, acquires pidfd custody plus the current host boot identity, and durably binds that exact process to the proxy before sending the fixed non-secret release marker that permits Hermes to execute. Missing authorization, custody failure, EOF, malformed release input, or release-pipe failure kills and reaps the blocked child and removes disposable runtime state. Requests before binding, after process exit, across a host reboot, or from any process that does not own the accepted TCP connection deny. For the tool-free manager route, only Hermes's semantically empty `tools: []` plus `tool_choice: "none"` decoration is removed before forwarding; non-empty tools and executable tool choices deny before the provider. Provider structured generation uses exact operation-specific proposal argument schemas, and Aegis still strictly decodes the completed response. Clear authenticated credential create/count/list/search/value-read operations bypass Hermes and execute directly through typed Aegis authority operations. Their interactive results are rendered from typed metadata as bounded labeled text rather than exposing serialized internal records; non-interactive CLI commands retain structured JSON. Inline create values are encrypted without entering model context. Exact-reference value retrieval checks active/revoked state, emits metadata-only audit, and intentionally renders terminal-escaped plaintext in session-scoped presentation state; terminal scrollback remains outside cleanup. No-echo intake remains the path when a value is not supplied conversationally. Its exact Core 15 local vocabulary is constructor-built in one typed registry. Only composer submissions can dispatch; command-position input is bounded, exact lowercase, non-shell parsed, and recognized, unknown, or malformed slash input never reaches Hermes. Alias canonicalization precedes policy and metadata-only audit. Model/runtime/tool/sensor/report/audit text remains typed untrusted presentation and cannot invoke commands. Canonical message-only responses may release the message string incrementally after a bounded parser recognizes the exact schema/kind/message prefix, but complete-envelope validation still determines turn acceptance; proposals and non-canonical responses remain fully buffered, and an invalid completed stream is visibly rejected. `//` removes one slash and then passes through ordinary ingress. The implemented core scan covers only named Aegis-native manager identity, authority, runtime/configuration, scope, route/readiness, and audit checks; it is not host monitoring. Endpoint scan forms and `/watch` return typed unavailable because no production adapter/source manager is installed.

Ctrl-D/terminal EOF is a normal `terminal_eof` exit, including when EOF races a runtime cancellation. Cleanup closes the process-authorized proxy before external-model unload verification. It first checks the exact running-model inventory and avoids a redundant scheduler mutation when the runner is already absent; a present runner is still explicitly unloaded and verified, and a genuine verification failure still fails closed and is reported.

Protected terminal intake explicitly enables bracketed paste and treats a complete framed multiline paste plus submit delimiter as one bounded no-echo value. Confirmation consumes an independently framed copy. A mismatch flushes queued protected terminal input before restoring the ordinary composer, preventing residual pasted lines from becoming a model turn. Detected credential-bearing ordinary-composer input—including known Doppler token prefixes—is blocked before Hermes even when trusted-local plaintext inspection would otherwise permit the exact local route. Terminals that do not implement bracketed-paste framing remain line-only; use a protected `--stdin` pipe for CLI `put`/`rotate` when exact multiline framing is unavailable.

The interactive presentation boundary is also Aegis-owned. Bootstrap's `basic` and `advanced` modes are presentation depth only: they invoke the same artifact-derived state machine and authorization paths. `basic` is the identified default; `details` or `advanced` reveals exact authoritative evidence before a presentation-owned approval, while `basic` returns to concise guidance. Changing depth cannot select a stanza, approve, mutate, reset, skip, or fabricate progress. Decline, invalid input, EOF, and interruption remain non-authorizing and resumable from verified artifacts. Certification must disclose its expected resource/time impact before approval. Rich composer sessions explicitly enable and restore terminal bracketed-paste mode; pasted CRLF is normalized and the complete bounded multiline envelope is scanned once before any model turn. Runtime and model output enters typed origin-classified events and is sanitized before measurement or rendering: CSI, OSC (including title, hyperlink, and clipboard forms), DCS, APC, PM, SOS, unsafe C0/C1 controls, carriage-return rewriting, dangerous bidi/invisible formatting, malformed UTF-8, and oversized layout work are removed or bounded. Stream updates are accumulated, sanitized as complete snapshots, required to remain monotonic, and coalesced in retained presentation state. Model-origin text cannot create authoritative events or populate trust/approval fields. Color-independent event roles distinguish `STATE`, `ACTIVE`, `QUEUED`, `ERROR`, and `ACTION` while preserving explicit Aegis/runtime/model origin labels. Rich terminal modes are restored after submissions and interruption; accessible/plain mode avoids cursor-dependent updates. This prevents terminal-control output from directly changing terminal state, but it is not a semantic guarantee that visually deceptive ordinary prose will never influence a human; origin labels and separate approval state remain required. The proxy strictly validates the complete request envelope, scans only untrusted user and prior-assistant message text (not the trusted Aegis system instruction or transport metadata), and scans complete bounded responses. Ordinary and Linux protected terminal reads are context-cancellable; protected intake restores the captured terminal state on success, failure, cancellation, and interrupted confirmation without echoing partial values. When principal and operational authority are ready but exact certification is absent or invalid, development bare startup and explicit `aegis manager` enter the authenticated degraded manager instead of bootstrap; production bare startup follows the authenticated service/readiness/bootstrap/browser-console path. It binds the same single stanza and mandate, emits authoritative startup audit, exposes deterministic local controls, reports the exact readiness reason and configured-candidate recertification command, and does not start Hermes, the proxy, Ollama inference, a cloud fallback, or an alternate model. Live certification applies the configured per-turn deadline and principal authority expiry as an overall deadline. Only schema-valid replies missing required conversational content enter a bounded three-execution loop with direct case-specific wording; operational, invalid-envelope, and other semantic failures abort immediately by default. Explicit `--continue-on-error` diagnostic execution may run later cases, but cancellation or authority expiry still stops the run and no failed or partial certification is published. An interrupted gateway client is permanently poisoned because Hermes events cannot be correlated safely after a timeout. No failed or partial certification is published. Bare startup owns Ollama readiness/load/unload, proxy and disposable safe-mode Hermes gateway lifecycle, exact certification/digest checks, rollback, metadata-only receipts, proposal confirmation, and protected no-echo mutations. All exits converge on bounded idempotent cleanup. The first SIGINT/SIGTERM requests graceful shutdown; a second signal uses the operating system's default action so cleanup cannot trap the process indefinitely. Scanner panic/timeout, malformed protocol, replayed or expired proxy calls, alternate models, public Ollama endpoints, certification drift, digest drift, and unsupported cancellation-safe protected intake fail closed. Certification is local and tuple-specific; it does not make any artifact a project default, and normal example configuration degrades honestly.

Model onboarding is a principal-authenticated, installed-only discovery and exact configuration transaction. The registry has no default; endpoints must be loopback; candidate name and immutable digest must match; previews disclose ownership and copy behavior plus original/result configuration digests; and publication requires explicit `[Y/n]` confirmation, rechecks the original digest, validates the generated configuration, syncs a mode-`0600` temporary, renames atomically, and syncs the directory. It provisions no profile, copies no model, and performs no certification or activation.

The self-updater trusts GitHub's release API and HTTPS delivery for this repository, rejects API and untrusted download redirects, permits only the bounded HTTPS GitHub release-asset redirect required by published assets, requires exact official-repository and stable publication metadata, and then requires the downloaded archive to match that release's `SHA256SUMS` entry before an atomic same-directory replacement. It never treats a Git tag as a published release and refuses downgrades. A checksum delivered beside an archive is corruption and consistency protection, not an independent signature or transparency proof. Package-manager installations should be updated with their package manager. Release recovery separately verifies the existing annotated tag signature, exact tag object/peeled commit, reproducible changelog-only release commit, and allowed `origin/main` relationship; it never force-pushes or mutates an existing tag.

The repository's CI and tag-triggered release workflow use the same installed-MVI verifier to require one exact clean local Git commit, build Linux/macOS archives for amd64/arm64, require every archive to contain exactly one root `aegis` regular file with mode `0755`, generate and verify `SHA256SUMS`, reject missing, dirty, malformed, or mismatched Go VCS metadata, verify the extracted native binary's injected stable version and exact embedded source revision, require an isolated bare non-TTY first run to deny without creating production state, and drive the extracted native binary through the no-key Registry/Loop/Graph/Queue/evidence/disposition vertical with durable rejection and historical readback. The optional pre-publication candidate verifier adds an exact clean source revision, verifies the candidate's exact embedded source revision, canonical non-symlink Hermes executable identity, strict bounded operator decision, one extracted native candidate digest, and repository-local rollback/withdrawal rehearsals. Local Git metadata and SHA-256 detect source/artifact mismatch relative to the checked worktree and retained manifest but do not authenticate the operator, Git host, Hermes publisher, or Aegis publisher; the decision file cannot authorize publication, and the local rehearsal is not proof that a remote withdrawal completed.

First-run principal configuration and valid-configuration operational-authority reconciliation are deterministic application code, not model authority. A valid configuration with exact operational-authority absence requires fresh host UID/username verification and explicit terminal confirmation before one empty generation is created. Non-interactive and ordinary command paths return `operational_authority_not_initialized` with exit status 2 and do not mutate. Existing dirty, corrupt, markerless, symlinked, wrong-owner, insecure, ambiguous, or populated legacy state is denied and never replaced. Stable binaries outside a worktree bind to the production root `~/.aegis`; the former `~/.argis` root and prior XDG defaults are migration inputs only, and meaningful coexistence or multiple legacy sources deny before mutation. Any executable inside the verified Aegis Git/module root is classified as development and binds to its ignored `.aegis` subtree, even when Go embeds a clean checkout tag as the module version. A copied development binary fails closed. One complete profile-owned layout feeds pre-configuration lifecycle classification and ordinary service construction, preserving separate configuration, generation-managed Badger session-authority persistence, encrypted bbolt credential authority/deployment identity, audit/checkpoints, certification, model, runtime, and cleanup paths. Development refuses production paths and production migration, and reset requires each binary's own exact profile layout. Initialization and apply-time revalidation jointly deny coexistence with populated or unsafe legacy `mandates`, `authority-contexts`, `authority-revocations`, or `sessions` trees. A clean install stages, syncs, no-replace publishes, and identity-verifies one empty Badger generation under `state/persistence/authority-v1` before configuration publication; digest-bound `ACTIVE`, `CLEAN`, and `DIRTY` markers make selection and open/close state explicit. It then revalidates operator identity, atomically links configuration mode `0600` without replacement, and syncs the containing directory. Interruption before that link resumes only when the existing authority is valid and empty. A corrupt `ACTIVE` marker or populated interrupted generation denies. Within the selected generation, one versioned binary registry owns metadata, mandate, context, session-index, transition-fact, and transition-root keys. Existing malformed, group/other-readable, symlinked, ambiguous, or unrecognized partial artifacts fail closed. `aegis reset` is destructive principal administration intended for development/testing. It operates before normal service construction, prints its execution profile plus an exact plan, required gateway stop-and-purge action, and irreversible credential/audit warning, and is restricted to that executable's exact profile layout. Repository-local development reset deliberately skips authority-passphrase authentication but retains the real-terminal explicit-`yes` boundary. Production release reset always requires a verifiable passphrase-file authority and authenticates its existing minimum-12-byte passphrase through protected intake before confirmation and independently a second time after `yes`, immediately before apply; missing, wrong, malformed, unavailable, or non-passphrase authority fails before mutation. After authorization, reset disables/stops/removes only the exact current Aegis-owned `systemd --user` unit and reloads the user manager before deleting any reset state. An absent unit file is a no-op only when systemd authoritatively reports `not-found` and `inactive`; foreign or byte-drifted unit bytes, loaded/active state without the expected file, inspection failure, stop failure, removal failure, or daemon-reload failure preserves reset state and denies. Exact legacy state beneath an external mode-`0775` XDG parent is removed through no-follow descriptors bound to previewed device/inode identity; the external parent is not chmodded or called an artifact, and the empty Aegis child can be retained. Local passphrase-encrypted or development authority/KEK deletion additionally requires state-root containment and Aegis format/schema evidence. External/systemd credential custody, normal Hermes/Ollama assets, external systems, and all downloaded models are preserved; the exact managed-model directory is preserved even when below state. Reset removes only recognized Aegis state including generation-managed Badger authority and the exact `fleet-v1` store, configuration last, and refuses unknown persistence files or schemas. Gateway purge and filesystem deletion are ordered but not atomic, so interruption can require inspection and separate-backup recovery. Development reset is not equivalent to production reauthentication, and neither path is a secure-erasure claim.
