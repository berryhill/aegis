## Client-only and non-service command families

* `version`, `version --provenance`: local executable/build metadata; no application-service backend. CLI read, not host mutation; retained exact CLI is appropriate, not a fabricated platform API.
* `config` inspect/validate: local config-loader operations, no app read DTO; raw configuration may contain transport/provider-sensitive data. Runtime discover and safe status DTOs do not expose raw config. Config write/setup/import remains an explicit host mutation.
* `design`, `charter` templates, `loops`/`graphs` constructors/builders: local artifact authoring/validation utilities, not backend mutations. Candidate canonical JSON can be collected in conversation and validated/published through the real service; no invented template backend.
* `runtime` installation, `gateway` install/start/stop/restart/status, `serve`, `console`, `update` check/apply and reset/backup/restore: local process/service, filesystem, executable/network or maintenance interfaces. Status/check reads are local diagnostics, not authority grants; mutation requires their explicit reviewed host workflow. No conversational shell bridge.
* Deployment projection enrollment/binding/compile/publish/pull/stage/activate/ack/revoke/inspect/rollback: specification only; no shipped CLI/API backend.
* Session preview actually issues a mandate; session start launches a clean runtime. These are protected authority/runtime effects, unlike stored session reads and exact confirmed revoke/terminate.
* Credential protocol operations remain separately typed and protected; platform.call never accepts credential values. Audit query is exposed only as inner platform.call audit.query, not unsupported direct legacy AuditQuery.
