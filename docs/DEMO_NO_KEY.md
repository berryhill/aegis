# No-Key Demonstration

Run from a clean checkout with Go 1.26.5+ and supported Hermes installed:

```sh
./scripts/demo-no-key.sh
```

The script creates an ignored, disposable workspace inside the checkout, builds a normally classified development executable beside the checkout's real `go.mod` and `.git`, initializes an empty generation-managed Badger authority only inside that workspace, and reports its `dev` version. It uses the current home when the checkout is beneath it; an automation checkout outside that scoped `HOME` receives its checkout parent as a process-local profile anchor so the same fail-closed development classification remains exercisable. It binds a mode-`0600` copied explicit configuration and copied charter to the current UID/username, discovers the real Hermes installation, validates a strict charter, verifies configuration redaction, and invokes the real disposable design boundary. Its nested `.aegis` paths are explicit demonstration fixtures, not development-profile defaults; production defaults remain under the selected profile anchor's literal `.argis`. It removes both its workspace and demonstration executable on exit and never points `HERMES_HOME` at the user's normal profile or touches canonical, production, or legacy state. This no-key path neither opens a credential authority nor invokes pinentry; pinentry behavior is exercised only by hermetic fake-helper and isolated authority tests.

Without an explicitly configured design provider credential, the final design turn is expected to fail. The script prints the real failure and explicitly does not claim a model-generated charter. If the operator deliberately configures a provider in the copied temporary configuration and source environment, the turn may succeed and Aegis will validate the returned proposal.

This demonstration proves checkout/development control-plane behavior and a real provider boundary; it does not invoke the fleet queue vertical, an installed release package, the browser console, host sandboxing, external audit anchoring, or individual-tool runtime attestation. Maintainers use `./scripts/verify-installed-mvi.sh` for the separate release-shaped exact single-file/mode archive, checksum, and version proof, fail-closed installed first run, credential-independent installed Registry → Loop → Graph → Queue → evidence/disposition vertical, and extracted-binary authenticated console proof. That verifier checks the embedded self-hosted Datastar asset and authoritative-empty surface, but it does not run a browser engine, prove real Hermes worker execution, publish a release, or broaden production/storage qualification. The stricter owner-selected pre-publication rehearsal is `./scripts/verify-release-candidate.sh`; it is separate from this no-key demonstration and records local binary/runtime/decision identity without claiming publication.

The bare manager is intentionally not recorded as a successful model conversation: no candidate artifact is downloaded or certified by this no-key workflow. Its non-TTY fail-closed dispatch and production rich/plain terminal path are covered by repository tests, including all Core 15 names through an isolated authenticated degraded manager, unknown/malformed local routing, literal `//` ingress, multiline/history/paste/help input, adversarial control-sequence sanitization, random-canary presentation absence, signals, cleanup, and terminal restoration. These tests do not claim host scanning or watching: the core scan is Aegis-native, and endpoint profiles plus `/watch` remain typed unavailable. `aegis manager model candidates` and `model route` can describe the no-default, no-download paths without changing state; discovery/configuration are intentionally omitted because they require an operator-owned local Ollama artifact.
