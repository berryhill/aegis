# No-Key Demonstration

Run from a clean checkout with Go 1.26.6+ and supported Hermes installed:

```sh
./scripts/demo-no-key.sh
```

The script creates an ignored, disposable workspace inside the checkout, builds a normally classified development executable beside the checkout's real `go.mod` and `.git`, initializes an empty generation-managed Badger authority only inside that workspace, and reports its `dev` version. It uses the current home when the checkout is beneath it; an automation checkout outside that scoped `HOME` receives its checkout parent as a process-local profile anchor so the same fail-closed development classification remains exercisable. It binds a mode-`0600` copied explicit configuration and copied charter to the current UID/username, discovers the real Hermes installation, validates a strict charter, verifies configuration redaction, and invokes the real disposable design boundary. Its nested `.aegis` paths are explicit demonstration fixtures, not the selected profile's production root; installed production defaults remain at the authenticated operator's literal `~/.aegis`, while former `~/.argis` is migration input only. It removes both its workspace and demonstration executable on exit and never points `HERMES_HOME` at the user's normal profile or touches canonical, former, or XDG legacy state. This no-key path neither opens a credential authority nor invokes pinentry; pinentry behavior is exercised only by hermetic fake-helper and isolated authority tests.

Without an explicitly configured design provider credential, the final design turn is expected to fail. The script prints the real failure and explicitly does not claim a model-generated charter. If the operator deliberately configures a provider in the copied temporary configuration and source environment, the turn may succeed and Aegis will validate the returned proposal.

This demonstration proves checkout/development control-plane behavior and a real provider boundary; it does not invoke the fleet queue vertical, an installed release package, the browser console, gateway installation, host sandboxing, external audit anchoring, or individual-tool runtime attestation. Maintainers use `./scripts/verify-installed-mvi.sh` for the separate release-shaped clean-source provenance, exact single-file/mode archive, checksum, version, embedded source-revision, fail-closed installed first-run, credential-independent installed Registry → Loop → Graph → Queue → evidence/disposition vertical, and extracted-binary authenticated console proof. The installed console verifier uses isolated repository-local state and a generated owner-only token file, reconstructs a complete durable Agent/Loop/Graph/Queue plus artifact/receipt/disposition chain, starts the candidate directly rather than touching the real user service, requires a concurrent candidate to fail its singleton lock without mutating the first socket, and obtains browser bootstrap through `aegis console` as a daemon-owned client. With real headless Chrome it follows rendered related-record links across exact immutable records, verifies direct load, reload, Back/Forward, server-side filters, and filter-preserving pagination, closes the inspector, and signs out. It also proves that the console document loads no executable client JavaScript and that the retained self-hosted Datastar asset remains directly servable but unloaded. It proves bounded Hermes queue execution through a registered protocol-faithful fake gateway, verifies gateway invocation and disposable-home cleanup, and supplies no provider credential; it does not prove live provider/model behavior, authenticate the source publisher, install or invoke `systemctl --user`, publish a release, or broaden production/storage qualification. The stricter owner-selected pre-publication rehearsal is `./scripts/verify-release-candidate.sh`; it is separate from this no-key demonstration and records local binary/runtime/decision identity without claiming publication.

The explicit manager is intentionally not recorded as a successful model conversation: no candidate artifact is downloaded or certified by this no-key workflow. These hermetic checks are release support evidence, not a live model transcript or certification result.
