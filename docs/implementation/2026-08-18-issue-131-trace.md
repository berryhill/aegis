## Existing endpoint-to-domain trace (current behavior)

1. `aegis` boots → `cmd/aegis/main.go` builds the service.
2. `internal/api/server.go` registers `/console/credentials` →
   `consolePage` → `parseConsoleDomain("credentials")` →
   `consoleSurfaceModel(surface, consoleCredentials)`.
3. `consoleSurfaceModel` looks at `surface.Credentials` (a slice of
   `app.CredentialView{ID, Type}`) populated by
   `app.Service.FleetSurfaceAs` from
   `s.Config.Credentials.ProviderAuth` only.
4. Each record becomes a generic `RecordModel{Key: index, Label: "X · environment binding", Summary, JSON}`.
5. `DomainCollection` (templ) renders the Credentials branch as
   `filter-row` + `RecordPanel` + a `credential-detail` aside that says
   "Select a credential / Inspect configured provider-binding metadata.
   Secret values and environment mappings are never read or shown here."

The trace stops at a placeholder; the bbolt authority has no path from
this surface. The plumbing gap is exactly the one the issue names.

## Root-cause analysis (not just symptoms)

The bbolt authority is structurally complete and proven
(`internal/credentials/bbolt/store_test.go::TestAuthorityCreateBindUseRotateRevokeAndNoPlaintextPersistence`
asserts no plaintext persists to disk). What is missing is the
**projection** of that authoritative state into the public surface.
A symptom-only fix would be to keep the current
`Config.Credentials.ProviderAuth` map and call it the "Credentials"
view; that violates the issue's "Project canonical encrypted credential
records and lifecycle into typed application/API read models" and
"Preserve active versus revoked state" acceptance criteria. The fix
must read from the bbolt authority via a typed read model, and it must
deny readiness cleanly when the authority is missing, locked, or
corrupt.

## Fail-closed semantics (security-sensitive behaviour)

The current code already refuses:

- Plaintext persistence in the bbolt file (`containsBytes` assertion).
- Wrong key, wrong deployment, second writer, unsafe mode, symlink
  path component, or unsupported filesystem (NFS/SMB/CIFS).
- Plaintext through a revoked record (`ErrRevoked`).
- Wrong-destination reads (`ErrRevoked`).
- Fuzzy references (`ErrNotFound`).
- Schema-version mismatches.
- Encrypted-decoding without key check (`credentials.Decrypt` validates
  the ciphertext hash and rejects key check failures).
- Passphrase authentication returning a generic error that leaks no
  envelope detail (`ErrPassphraseAuthentication`).
- Browser-launched mutation: no form action, no mutation route, no
  datastar write, no `localStorage`, no `sessionStorage`,
  no `data-on:` (asserted by `TestConsoleSourceForbidsUnsafeActiveContent`).
- Browser-selectable identity, stanza, mandate, authority (asserted by
  `TestAuthenticationExplainsAuthenticatedHostBootstrapHandoff`).

The implementation must preserve all of the above when adding the
new surface and typed read models. In particular: the proposed
"prepare credential" and "prepare vault backup" interactions must be
**proposals** rendered into the page (review text + the exact CLI
command), not a POST handler. The "browser state cannot authorize"
invariant is asserted today by every other surface; the credential
surface must join that contract.

## Plan: implementation boundaries (next step)

1. **`internal/credentials/custody_status.go` (new)** — read-only
   `VaultStatus` summarising: database path, deployment ID, custody
   mode, KEK id/version, schema version, last-clean-shutdown, and
   initialized/missing/locked/degraded. Distinct states; never
   includes key material.

2. **`internal/app/credentials.go` (new)** — add
   `Service.ConfigureCredentials(repository, custodian)`,
   `ListCredentialsAs`, `CredentialView` (rich), `VaultStatusAs`,
   and update `FleetSurfaceAs` to populate
   `Credentials []CredentialView` from the bbolt authority when
   configured, with `Readiness["credentials"]` classifying
   initialized / empty / locked / unavailable / denied / degraded.
   Config-only `ProviderAuth` map is never the source of truth.

3. **`internal/api/console.go`** — replace the `CredentialView` shim
   with a rich `consoleCredentialRecord` model that surfaces
   `ID, Reference, Kind, Status, CurrentVersion, CreatedAt, CreatedBy,
   RevokedAt?, Revocation?, VersionHistory, KEKSummary, BackupStatus,
   VaultStatus`. Add `consoleActions` for `prepare_credential` and
   `prepare_vault_backup` (review-only proposals).

4. **`web/console/components.templ`** — add
   `CredentialWorkspace(surface)` and `CredentialInspector` with:
   - Status filter (All / Active / Revoked) and exact ID search.
   - One record card per credential with kind, reference, status
     chip, current version, last change, and binding count.
   - Detail panel with: vault summary, record provenance, full
     version history, custody mode, KEK metadata (id+version, not
     key material), backup status, prepare-credential preview, and
     prepare-vault-backup preview.
   - The previews are inline `<pre>` blocks showing the exact
     `aegis secret put` / `aegis secret backup` command; they
     **never** POST. They assert "browser state cannot authorize
     credential mutation".

5. **`web/console/components_test.go`** — extend the existing
   `TestAuthenticatedDocumentUsesNativeNavigationInspectionAndLogout`
   contract; add a `TestCredentialsRendersActiveAndRevokedDistinctly`
   test that fails if the templ source contains a `</span><script>`

6. **`internal/api/console_test.go`** — extend
   `TestConsoleSurfacePreservesContextualReadinessAndCredentialMetadata`

   one case for missing authority, one for locked custody

7. **`internal/credentials/bbolt/store_test.go`** — add a
   `TestStoreRoundTripPreservesAllMetadataFields` test ensuring the

8. **Launch assets** — update `CHANGELOG.md`, `docs/THREAT_MODEL.md`,
   `docs/ARCHITECTURE.md`, `docs/CREDENTIAL_AUTHORITY_SETUP.md`, and

## Risks and constraints

- **Visual fidelity** without OpenDesign: I will reconstruct the
  surface from the typed contract and the design's stated scope. The
  `TestCredentialsRendersActiveAndRevokedDistinctly` test plus the
  existing `TestConsoleSourceForbidsUnsafeActiveContent` protect the
  security invariants; the operator may still request visual review
  before merging.
- **No-go constraint from the issue**: "make credential setup a
  release-defining gate for credential-independent fleet control" is
  explicitly out of scope. The credential readiness must not be
  unioned with `registry/loops/graphs/queue` readiness in a way that
  makes missing custody turn fleet reads `degraded`.
- **No plaintext in HTML/JSON/logs**: the typed view model must omit
  every ciphertext field. Tests will scan rendered HTML and the
  JSON marshal output.
- **No `data-on:` / `data-bind:` / `localStorage` / `sessionStorage` /
  `<script>`** (asserted by existing tests). The credential surface
  must not introduce any.
- **Trust stanzas, mandates, audit, and browser-authority
  invariants** all already enforced by the surface, the console
  manager, and the audit authority. The new read path must not
  widen the boundary.
