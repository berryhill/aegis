# Release packaging compatibility with v0.2.29

Official four-platform assets omit only top-level `-trimpath`: Go 1.26.9
otherwise omits the actual `-ldflags` build setting needed by the installed
v0.2.29 updater to authenticate Version and SourceRevision. The real unchanged
`-s -w -X ...Version=... -X ...SourceRevision=...` linker arguments remain.
No binary bytes, module versions or VCS metadata are forged or patched.

This is a packaging compatibility choice, not a new source/version admission
policy. Exact clean Git revision, Go VCS stamping, repository identity,
archive shape/names/modes, checksums, native provenance, installed vertical and
console proofs, parent CI evidence and publication checks remain required.
Existing credential/signing policy and operator authorization are unchanged.
The release verifier additionally tests actual archives against frozen v0.2.29
production Prepare/Identity and candidate validation before publication.

Removing trimpath exposes real compiler source paths and makes output sensitive
to checkout and toolchain locations. Do not claim location-independent binary
reproducibility or path privacy. Official GitHub Actions builds use public runner
checkout/toolchain paths; private local builds can expose private operator paths
and are not official publication evidence. No new secrets are embedded. Skill
bundle reproducibility is independent and unchanged.

Launch-asset review: packaging/verifier and this focused report changed.
README, LICENSE, SECURITY, CONTRIBUTING, CODE_OF_CONDUCT, CHANGELOG, threat
model (docs/THREAT_MODEL.md), architecture, quickstart, no-key demo, terminal
recording and contributor issues were inspected for packaging impact; none
promise trimpath/path-independent binary reproducibility. Existing workflows
remain unchanged. Release binaries/checksums must be regenerated by the normal
exact clean-source release gate; local compatibility evidence is not publication,
installation, service readiness or authenticated dashboard acceptance.
