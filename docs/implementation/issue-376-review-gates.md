# Managed contribution qualification gates

The narrow dependency-free Go qualification profile now pins the resolved Go distribution, not just its driver: compiler/linker, standard-library and assembler inputs, distribution configuration, headers and libraries are hashed in bounded controller custody. Native processes pin GOROOT, target OS/architecture, local toolchain, disabled GOENV/workspaces/network dependencies, CGO-off and fixed native flags. Toolchain drift, unsafe permissions, symlinks and missing inputs deny. GOPATH module caches and distribution documentation/test trees are not compiler inputs and are excluded. The source inventory still covers all repository files except Git metadata.

Review is a deliberately narrow **operator-approved exact-content review**, not an automated semantic security certification. An immutable approved policy lists actual security and launch assets with approved baseline/candidate hashes; explicitly reviewed nonapplicable entries require a reason and cannot exempt a file. The controller computes changed/unaffected/missing identities and persists a candidate/source/policy-bound immutable per-asset ledger. Every required native security and explicit denial criterion must also pass. Caller/model PASS text is not evidence. New asset bytes require a new exact policy approval.

The controlled native and Queue fixtures contain real README/security/generated assets and executable argument-denial checks. They are synthetic runtime qualification, not real-provider or production-repository review. AcceptedCandidate reloads the immutable chain and revalidates current source/index/toolchain/executable identity, so post-review documentation/generated changes deny handoff. No release, publication or live activation is implied.
