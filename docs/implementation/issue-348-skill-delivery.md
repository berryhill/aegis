## Obligation

service, strict application types and evidence semantics. Documentation and help
are advisory; neither structural coverage nor archive validation proves behavior.

## Candidate scope

- Correct direct-new Loop submission versus immutable historical Graph replay,
  retained task execution versus separate publication and exact Run, compatible
  same-intent recovery, cumulative budgets and foreground execution.
- Separate stable Hermes version eligibility from exact provider-source transport
  qualification, selected-file evidence from trusted native Go checks, and partial
  managed v6 candidate acceptance from the complete contribution contract.
- Keep one canonical contribution contract. Packaged skills provide an immutable
  public reference to that contract, not a second copied acceptance oracle.
- Extend the existing operation matrix with `owning_service_cli` classifications.
  Source AST coverage checks the actual dispatch switch rather than equating help
  nodes or REST registrations with online support. `advisory` setup approval is a
  human-only protected path, never model permission to approve.
- Reuse existing manifest refresh, archive construction/verification and explicit
  managed installation. No installer, package manager, daemon or skill family is
  added. No fleet profile or live configuration/service change belongs here.

## Verification surfaces

`TestPackagedFleetRecipes` installs the canonical archive into isolated state and
exercises installed CLI registration, local public v5 construction, separate
validation/publication/exact Run, retained execution, preparation recovery,
result/evidence readback and failure/distinct-task continuity through actual Unix
owning-service transport and durable stores. The runtime and authority fixtures
remain synthetic. It is not an agent-behavior evaluation or actual-provider proof.

`TestInstalledOnlineLoopPublication` additionally exercises strict registration,
exact readback, idempotency, malformed/unknown input and target/authentication
boundaries. Existing authority, ownership, stale-reference, replay and budget
regressions remain mandatory. The frozen-executable test input permits testing
the actual candidate bytes without silently rebuilding or overwriting them.

`TestOwningServiceInventoryMatchesDispatch` and `TestDistributedOperationMatrix`
are structural contracts only. `TestDeliveredGuidance*` prevents identified prose
regressions but does not execute a product journey. Managed installation tests
cover source/checksum binding, unmanaged/symlink destination refusal, local edits,
interruption, locks, update and rollback. Fresh Hermes discovery and effective
project-context loading must be checked independently against the isolated install.
Existing sessions do not adopt changes merely because installation succeeds.
