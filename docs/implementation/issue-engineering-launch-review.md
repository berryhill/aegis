# Issue engineering launch/security review

## Implemented source boundary

The opt-in engineering successor accepts one runtime input, `github_issue_url`.
Definition-time policy fixes the repository, roles, immutable checks, offline
locked dependency bundle, bounded engineering prefixes/assets and generated-pair
policy. The owning service now performs retained managed prose inspection,
issue-specific scope derivation, pre-seal role/prerequisite decision delivery and
prepared-proposal binding. Legacy fixed-file profiles retain their compatibility
path; their fenced issue block is not required by the engineering successor.

The Console offers the URL-only Run form and retained decision projection
(purpose, role, Agent/Charter, plan digest, contract/candidate, status and expiry).
It cannot approve or apply foundational authority. Independent protected review
and fresh admitted effects remain mandatory; missing transport is unavailable,
not an invented pending approval. See [the engineering contract](../issue-derived-engineering.md).

Native generation is separately authorized, exact-pair and candidate-bound.
Pinned offline templ generation retains full preimages/modes and input, tool,
dependency and output custody. Read-only exact generated consistency and actual
rendered checks remain independent of builder-proposed source/tests/model PASS.
Native repository code is not sandboxed; bundle and host approval remain trust
decisions. No authority, verifier, TTL, budget or protection checks were relaxed.

Retained parent proof `parent-real-templ-joined.log` shows 32 planning calls within
the original 128-turn budget and actual native bad-candidate rejection, same-builder
repair and fresh-tester acceptance after real templ generation/render checks.

omitted controller-derived `web/feature_templ.go` from its allowed files, while
the accepted candidate correctly included that changed output. The corrective
fixture uses the sealed scope and retains an explicit negative requiring denial
when the generated output is omitted. The corrected joined proof
`child-real-templ-delivery-scope.log` PASSED in 247.156 seconds: native acceptance,
`local_target_completed` delivery-preclosure, then canonical disposition, artifact
and verification receipt readback. Historical failed evidence is preserved.

The productive delivery controller had the analogous template-scope projection.
It now derives files through `contribution.BindLoop` against the exact sealed
contract. Focused admission/controller/scope/remote-capability tests pass,
including changed-scope denial and detached-slice checks. A repeat of the complete
joined journey on that final source is handed to the parent in
`child-real-templ-final-source.log`; its launch alone is not a second PASS.

This is controlled local owning-service/native proof, not live-provider,
installed Console, protected GitHub merge, released binary or main deployment
qualification. Fresh independent frozen-candidate acceptance and the parent's
requested external tiers remain separate. Current source/binary are not frozen.
