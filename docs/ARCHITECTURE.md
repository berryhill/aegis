The model proposes; it never authenticates, approves, or provisions. Design uses a disposable Hermes gateway process with the empty `no_mcp` toolset, bounds requirements and accumulated proposal output to 1 MiB, and accepts exactly one enveloped charter proposal. Aegis separately bounds import, then strictly decodes, validates, canonicalizes, digests, and persists it.

Provisioning currently supports only atomic creation of deterministic Aegis-owned mapping files. File modification, Hermes profile creation, MCP/plugin configuration, gateways, services, cron, and external network effects are explicitly classified and denied.

Operational launch resolves one stanza into one mandate, one credential binding, one set of Hermes toolset arguments, and one clean process/home. Selection evaluates verified subject, method, issuer, freshness, and trusted environment data; a requested stanza only filters already-authorized matches. Zero matches, overlapping policy, stale authentication, and multiple matches fail closed. Stored charter bytes and digests are revalidated before use, and mandate authority is compared exactly with the selected stanza before launch. `toolset_verification: launch_arguments` records argument-level verification rather than individual-tool runtime attestation.

Canonical domain ownership is bounded rather than represented by one mutable lifecycle aggregate. `core` owns subject, stanza decision, effective authority, mandate, immutable per-session authority context, session, and provisioning artifact/receipt records. It defines internal typed repository contracts without a generic kind, update, or replacement operation. The generation-managed Badger store implements them through one versioned binary key registry for metadata, mandates, contexts, the session-uniqueness index, transition facts and roots, canonical commands and facts, receipts, current projections, and derived outbox entries. Length-delimited identifiers keep prefixes isolated; strict decode rejects unknown versions/families, malformed lengths, invalid identifiers, zero sequences, and trailing bytes. Context plus session index creation and legacy fact plus root replacement are each conflict-detecting transactions. The command boundary atomically writes one accepted command, its controller-authored fact, durable receipt, current projection, and outbox entry; any collision or validation failure rolls the entire transaction back. Reads reject key/value identity, canonical replay, receipt linkage, projection, or outbox mismatches.

`internal/reference` is the single low-level owner of cross-domain `DigestRef` and `RevisionRef` values. A digest reference binds one validated stable identity to an exact lowercase `sha256:` digest; a revision reference additionally binds one positive immutable revision. Their versioned deterministic JSON codecs accept exactly one object and reject invalid UTF-8, malformed or incomplete values, unsupported schemas, unknown fields, duplicate object keys, and trailing data or values. The package is standard-library-only, may not import another Aegis package, and carries no lookup, latest-revision fallback, authorization, or authority-union behavior. Architecture tests enforce its canonical type ownership and dependency direction.

`internal/registry` is the bounded fleet-control participant domain. Its deterministic current-fleet fixture adapter validates one closed schema and discovers candidates by immutable `(kind, fleet ID, source ID)` identity without scanning profiles, environment, credentials, dashboards, or legacy handoff stores. Registration permanently binds that source identity and stable Agent ID to revision 1. Canonical Agent revisions preserve exact source, runtime, owner/accountability, lifecycle, charter revision/digest, capability declarations, and policy references under a content digest. Repositories have no update/upsert operation: exact registration replay is idempotent, conflicting identity or revision publication denies, revisions must be sequential, and retirement is terminal. Executable resolution requires an exact identity/revision/digest and an enabled lifecycle; it never resolves `latest`. The shared application path uses the Badger `fleet-v1` implementation for restart-durable immutable facts and atomic repository-assigned audit. Public CLI/API registration and reads require the configured principal; neither transport nor Registry records grant stanza selection, mandate, or runtime authority.

`internal/loop` owns immutable typed Loop definitions and deterministic validation records. A revision contains bounded typed ports, steps, input mappings, transitions, exclusive branch gates, joins, retry limits, terminal outcomes, and evidence claims. Canonical encoding and digesting are deterministic; strict decode rejects malformed or incomplete data, invalid UTF-8, unsupported schemas, unknown fields, duplicate keys, and trailing values. Validation fails closed on duplicate or missing identifiers, invalid entry/targets, transitions from terminals, incompatible mappings, unbounded or misplaced retry behavior, invalid gates/joins, unreachable structure, cycles, and incomplete evidence claims. Publication records bind the exact Loop revision/digest and validator result/digest, but this package performs no storage, authorization, publication side effect, queue admission, runtime launch, or execution.

`internal/graph` owns immutable coordination definitions and deterministic validation/run-snapshot records. Each node binds one exact Agent revision/digest and one exact Loop revision/digest through `internal/reference`; dependencies and Graph/node input/output mappings are typed, bounded, uniquely targeted, and acyclic. Revisions form a create-only contiguous predecessor-digest chain and carry exact policy-digest references. Strict canonical codecs reject invalid UTF-8, malformed or incomplete values, unsupported schemas, unknown or duplicate fields, trailing data, and digest substitution. Historical validation results bind the exact revision and validator. Lifecycle selection is a separate draft/active/retired record. A run snapshot canonicalizes typed inputs and seals the exact Graph plus deduplicated Agent and Loop references under its own digest. These records carry no subject, stanza, mandate, authority context, queue state, runtime state, artifact, or disposition; callers must resolve exact references and perform fresh authority admission separately.

`internal/persistence/fleet` is the narrow durable fleet boundary. Its Badger adapter atomically stores Registry registration/revisions, Loop and Graph revisions plus exact validation facts, accepted or rejected submission outcomes, queue/run records, claims/attempts, runtime-artifact metadata, verification receipts, terminal dispositions, exact canonical replay bindings, and repository-assigned hash-linked audit facts. Accepted submission resolves the persisted Graph, Graph/Loop validation, enabled exact Agent revisions, exact Loop revisions, normalized inputs, and derived reference sets inside the transaction that creates the snapshot, submission, queue item, Graph run, queued transition, request binding, and audit fact. Rejection creates one durable negative outcome under the same idempotency namespace. Initial claim is single-winner and atomically binds one queue item to one claim, attempt, claimed transition, and audit fact after resolving the exact Loop execution. Completion independently reloads each persisted content-addressed verification receipt, atomically validates claim/attempt/authority/artifact/receipt/policy causality, and creates evidence metadata, one disposition, the terminal queue transition, and audit fact. Missing, substituted, disabled, retired, mismatched, corrupt, conflicting, or late-collision input denies without partial state. This adapter is not application authentication, lifecycle selection, authority admission, or a runtime adapter.

`internal/queue` owns strict bounded canonical submissions, durable rejections, queue items with exact dependencies, claims/leases, retries, cancellations, append-only transitions, and rebuildable non-authoritative projections. `internal/execution` owns strict bounded Graph runs, Loop executions, attempts, and distinct terminal states with exact parent/child causal IDs and revision/digest references. `internal/evidence` owns runtime artifacts and verification receipts; `internal/disposition` owns immutable terminal decisions. Persisted claims, authority references, artifacts, receipts, and dispositions are facts, not grants; they cannot authenticate a worker or authorize Hermes.

The Agent Registry console adds separate bounded registration review and execute adapters over that shared service. Review validates the canonical charter, requires its creator to match the configured principal, requires the exact revision and digest to exist already in the charter store, resolves exactly one deterministic current-fleet source, and derives revision 1 without persistence. Execute consumes a subject/session-bound single-use receipt, recomputes the proposal, and registers through the shared service; it does not import the charter or provision an agent. Lifecycle mutation binds the exact current revision and digest, permits only legal append-only transitions, and requires explicit retirement confirmation.

`internal/orchestration` is a narrow application service over these ports. It binds registration, Loop/Graph publication, Loop activation/retirement, and Graph submission to an authenticated subject and one exact freshly admitted authority context, preserves immutable historical references, produces durable submission rejection where possible, and exposes action-specific contextual readiness. Loop publication and lifecycle reload one exact enabled publisher Agent revision and require its charter/runtime binding to match admitted authority. Publication seals immutable Agent, authority-context, mandate, stanza, runtime, charter, and validation provenance; lifecycle appends digest-chained active or terminal retired events. Readiness, provenance, and lifecycle records are diagnostic facts and never grant authority. Public Cobra resources and protected `/v1/agents`, `/v1/loops`, `/v1/graphs`, and `/v1/queue` routes call this shared boundary; Loop lifecycle mutation is currently the protected HTTP `PUT /v1/loops/:loop/lifecycle` operation. The authenticated console exposes bounded Agent registration/lifecycle forms, reviewed command intents for Loop publication/lifecycle, exact Graph compose/publish and typed-run forms, and closed Execution Queue process/reclaim/terminal controls; credential records remain read-only. The queue operation adapter accepts one closed CSRF-protected operation, reloads the exact item, generates operation IDs server-side, and calls these same authenticated application services. Browser input never selects authority. The controller-side `QueueWorker` supports only one exact Graph node and one executable Loop action. It repeats fresh admission before claim, runtime effect, each evidence verification, and successful disposition; routes only an exact registered runtime; provides an explicit deterministic credential-independent no-key adapter and a bounded Hermes gateway-turn adapter with hard limits and a disposable home; stores output by digest; and commits independently reloaded evidence metadata, disposition, transition, projection, and audit atomically. Unsupported Graph shapes deny before claim. The installed-MVI verifier drives the extracted native binary through the bounded Hermes vertical with a protocol-faithful fake gateway and verifies cleanup. This is not live-provider/model acceptance. Graph lifecycle application, automated retry/reclaim/cancellation scheduling, dirty-store recovery, and multi-node scheduling remain launch work.

The adjacent canonical authority codec makes mutation intent and deterministic reconstruction explicit. Its closed activate/revoke/expire commands bind immutable command identity, mandate/context target, expected sequence and previous digest, authenticated actor, issuance/half-open expiry window, reason, and canonical digest. Accepted commands correspond one-to-one with immutable controller-authored facts. Portable replay strictly decodes versioned records and verifies command/fact identity, ordering, chain preconditions, context binding, legal transitions, time bounds, uniqueness, and digests before deriving a projection. Exact retries, including retries after the original command window, return the existing replay-verified receipt without appending another fact or outbox entry; reuse of a command ID with a different digest denies. Current-projection and admission reads replay canonical history and compare it with stored derived state inside one Badger read transaction. Only that replay-verified path derives a committed-authority position binding context ID, sequence, fact digest, and projection digest. Canonical authority audit delivery consumes verified outbox entries in strict sequence and creates deterministic metadata-only evidence for each exact position; exact retries add nothing, while malformed, gapped, reordered, or substituted state fails closed. The grant-producing readiness read evaluates ordinary admission and requires audit evidence to equal the current committed position in the same Badger snapshot, otherwise it denies with `audit_delivery_lagging`. Receipts, projections, outbox entries, positions, and audit evidence remain non-authoritative. This processing boundary is internal and is not yet exposed as a CLI/API mutation workflow.

The Badger repository now contains the canonical command-processing, authority-audit delivery, and exact-position readiness primitives, but existing application service mandate, context, revocation, launch-admission, and reset workflows are not yet migrated to them; their persisted formats and runtime behavior remain unchanged. `execution` owns dispatch and runtime-turn state plus the narrow launch/admission contract. `evidence` owns content-addressed runtime artifacts and claim-specific verification receipts. The Hermes adapter receives only an immutable launch contract and fresh admission decision. Evidence, receipts, projections, outbox entries, committed positions, authority-audit evidence, and transition roots cannot select a stanza, issue a mandate, authorize execution, or declare domain success. See `specs/CANONICAL_DOMAINS.md`.

The exact post-Track-A storage envelope is specified in `specs/STORAGE.md` and enforced in executable architecture and qualification tests. Session authority plus the separate fleet-definition and fleet-lifecycle planes use Badger `v4.9.5`; credential custody uses bbolt `v1.5.0`; all are qualified only for Linux/amd64/ext4 with the documented single-Aegis-process and engine-specific durability settings. Both fleet planes share schema `fleet-v1` and the exact `state/persistence/fleet-v1` root. Readiness requires the exclusive writer lock, restrictive modes, a 256 MiB reserve, completed migration state, and a clean close or verified dirty recovery. The adapter implements atomic accepted-or-rejected submission persistence, dependency-gated attempt-bounded claims, durable expired-lease retry/reclaim, queued-or-claimed cancellation, validated rebuildable queue projections, and atomic terminal evidence/disposition persistence. Public application wiring and a release-shaped installed fake-gateway Hermes proof now exercise the narrow initial execution path. Migration/backup/recovery machinery, dirty-store recovery, automated lifecycle scheduling, multi-node scheduling, and live-provider acceptance remain unimplemented. Release cross-builds for macOS and arm64 prove packaging, not persistence qualification; the native installed proof does not broaden the qualified envelope. Canonical facts, rebuildable projections, operational metadata, blobs, runtime state, and credential custody have separate owners and failure semantics. A derived record, audit-delivery marker, lifecycle marker, runtime home, or partial write in another store cannot complete or reconstruct missing authority.

Authority lifecycle mutation is serialized across cooperating processes by a root-scoped no-follow mode-`0600` `flock` coordinator. An open store holds a shared lease for its complete lifetime; initialization and maintenance operations require an exclusive, context-cancellable lease. On qualified Linux, lifecycle markers, generation moves, failed-staging cleanup, and GC deletion are relative to no-follow directory descriptors rather than re-resolved mutation paths. Initialization and candidate-producing maintenance require bounded output space plus a fixed 256 MiB reserve. Export requires a closed clean identity-verified active generation and publishes a bounded deterministic representation atomically without replacement. Logical recovery verifies the backup, imports canonical records into a fresh inactive generation with new identity, omits stored authority projections, and rebuilds those projections transactionally from canonical command/fact replay. Native recovery instead selects an exact verified retained generation. Activation, rollback, and native recovery monotonically advance activation identity and return a typed outcome recording whether selection committed and whether the previous generation retired, including when later cleanup or sync reports an error. Garbage collection captures and revalidates device/inode identity and removes only verified non-active generations under an explicit retention count. The backup checksum provides integrity detection, not encryption, a signature, publisher authentication, or independent rollback protection.

The optional credential authority is a separate administrative data path. It stores independently encrypted immutable versions, exact agent/stanza/deployment/scope bindings, revocations, and metadata in one deployment-bound bbolt file. It validates schema, structural integrity, filesystem ownership/mode, and a KEK-authenticated sentinel before serving administration. The injected passphrase service is the single authority-passphrase edge for onboarding, secret administration, manager startup, and service opening. It selects an explicit validated absolute helper or conventional `pinentry`, executes it directly with an allowlisted desktop/session environment, bounds and validates the Assuan exchange, and returns process-local bytes only. Create uses two fresh interactions; unlock retries only envelope-authentication failure. Pre-`GETPIN` unavailability may use a real-terminal no-echo fallback, while cancellation and post-interaction failures fail closed. Systemd custody is a two-boundary resumable transaction: Aegis first records the exact external prerequisite, then—only after systemd delivers the KEK and the principal separately confirms—creates the database without copying or modifying the credential. Authority passphrase and administrative CLI intake remain outside the model and avoid argv; manager inline credential-create values may enter only the authenticated exact-local-model session described below. Inspection returns metadata only. Consistent backups use bbolt read transactions and do not include the KEK.

The optional Linux broker is an active model-visible authority-to-downstream edge for only `github.get_repository.v1`. It derives the exact binding and `github-api` destination from current Aegis state, applies the credential internally, and returns a bounded field allowlist. Its pathname socket authenticates a distinct runtime identity with `SO_PEERCRED`; a 256-bit capability is bound to the exact live session, mandate, charter, deployment, stanza, PID/start token, and expiry. Fresh 128-bit request IDs and bounded deadlines are deduplicated in a finite per-capability replay cache. Session cleanup revokes the capability and removes its file. For the exact `aegis` toolset, the adapter generates one disposable MCP server mapping and queries the live gateway, denying launch unless only `mcp__aegis__github_get_repository` is registered. Operational provider authentication continues through the configured environment-binding path. This remains application-level mediation, not host or network confinement. See `CREDENTIAL_BROKER.md`.

The API uses the same services as Cobra. Bearer authentication is transport-only; Linux Unix peer credentials create the Aegis subject. TCP TLS is optional transport encryption and does not map a principal identity. When configured, the server listens on both its protected Unix socket and TCP address so principal-only local requests and the browser shell share one application-service authority boundary.

New gateway onboarding generates the bearer into an absolute owner-only token file and stores only its path in configuration; the exact unit, preview, argv, and environment contain no reusable value. After separate complete transport and unit previews, bounded `[Y/n]` confirmations accept Enter, `y`, or `yes` and decline every other answer, EOF, cancellation, or input failure without mutation. An explicitly confirmed deterministic `systemd --user` unit can supervise `aegis serve` under the configured principal's same account. Apply re-derives and revalidates the complete approved executable, configuration, unit bytes, SHA-256 digest, Unix socket, console origin, and principal immediately before mutation; an existing non-identical or unsafe unit denies rather than being replaced. Activation then executes explicit publication, daemon reload, enable/start, exact loaded-fragment validation, and authenticated audit-current readiness phases. Start, stop, and restart repeat the exact-unit check before mutation, validate systemd's loaded fragment afterward, and wait within a bounded context for observed active or inactive state. Start and restart additionally require authenticated audit-current readiness. The readiness probe validates bearer transport plus kernel Unix peer identity without appending a new authentication audit event that would stale the projection it is observing; it advances only pending, nonzero, verifiable audit work through the protected bounded delivery route, then retries readiness. Authorization denial, terminal or unverifiable audit state, malformed response, and timeout fail closed. Successful lifecycle operations emit typed results with exact unit provenance and observed state. Failures carry the exact phase, last readiness response, and joined rollback errors. Compensation preserves pre-existing exact unit bytes and active/enabled state, removes only a newly published unit, and reverses only gateway state introduced by the apply. Install uses only the user's service manager and does not enable linger. Status reports observed activity and linger rather than claiming logout survival unconditionally. Uninstall disables and removes only the exact expected unit and preserves Aegis state and external credentials. This is process supervision and sole-online-owner reconciliation, not a root service, separate UID, sandbox, or persistent Hermes runtime gateway.

Before touching a pre-existing Unix socket, `serve` creates/validates and nonblock-locks the current-owner mode-`0600` single-link `<unix_socket>.lock`. Lock contention denies before stale-socket removal, making one daemon the cooperating-process owner of the transport and authoritative stores. While the configured socket exists, direct store-backed CLI construction fails with `control_plane_online`; it does not silently open stores beside the daemon. `aegis console` is a narrow daemon client that prints the configured `/console` URL and the `principal_password` authentication requirement without issuing a browser session. `aegis manager` is a separate narrow terminal client: after Unix peer plus bearer authentication, the gateway issues one bounded in-memory session fixed to the authenticated principal and `secrets-manager` stanza; each typed slash request repeats transport and session authorization before the single application service executes it. The client holds its token only in memory, revokes it on clean exit, never opens gateway-owned persistence, and has no offline fallback. Bare development and production startup add an observational admission layer before authority-store inspection: exact installed bytes, systemd's loaded fragment, the loaded `ExecStart` executable and complete `serve --config` argv, activity, and authenticated audit-current readiness must identify the sole online owner. Recovery after the state root is recreated validates the loaded fragment and complete `ExecStart` before restarting the exact gateway, then revalidates both loaded identities before readiness. A foreign fragment, stale executable, or stale configuration denies before lifecycle mutation. A healthy unit offers explicit console, terminal, and exit actions with default exit. For a plaintext loopback origin, console invokes `xdg-open`, macOS `open`, or Windows `rundll32` directly with the clean configured `/console` URL as one argument. Browser launch carries no authentication material and does not establish a session. Terminal launches the same manager gateway client without opening a second writer. Missing, expired, revoked, or interrupted manager authentication denies and requires a fresh invocation. Mismatched/unhealthy units and dirty/corrupt closed authority deny before browser launch. Unsupported scope or launcher failure returns an actionable error without issuing authentication material. Other store-backed CLI resources are not yet transported through the daemon; operators must stop the gateway before using those direct command paths.

The embedded `/console` shell is a presentation adapter, not an identity provider or authorization service. Every new browser session requires exact-origin verification of the enrolled principal password. Successful verification creates an in-memory browser session capped by both its configured lifetime and the principal-authentication expiry; the CLI, Unix transport, API bearer, and browser launcher cannot mint or exchange a passwordless browser session. The browser receives only an `HttpOnly`, `SameSite=Strict`, path-scoped cookie and a session-bound CSRF value. It receives no reusable API bearer and writes no authentication material to URL, HTML, local storage, or session storage. ## Execution Queue lifecycle and history

The controller exposes manual authenticated queue lifecycle services over the same application layer used by Cobra and Echo. Every operation reloads the immutable queue item, snapshot, GraphRun, and authority context, then repeats fresh admission before persistence. Claims create bounded attempts. Retry/reclaim returns the same queue item to queued state and preserves one GraphRun and one LoopExecution while the next claim creates a new numbered attempt. Reclaim requires lease expiry; ordinary caller assertions cannot preempt a live runtime.

Terminal cancellation, expiry, authority revocation, retry exhaustion, denial, failure, and success persist separate reasoned outcomes. The read model joins immutable definitions and snapshots with GraphRun, LoopExecution, attempts, claims, transitions, retries, cancellations, evidence, receipts, artifacts, and disposition so historical execution remains reconstructable after definitions change. The templ console projects filters, provenance, dependency state, timeline, and action eligibility from those facts; it is not an authority source. Lifecycle scheduling and multi-node coordination remain outside this bounded MVI.
