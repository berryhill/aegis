## Bounded producer → consumer source candidate (#317)

paired raw v2 nodes or paired managed selected-file v7 nodes, one outer Queue
attempt, and no general scheduler. v7 pins one initially absent selected output
per separate non-nested workspace, exact UTF-8 verification and 1–2 implementation
passes per node. The consumer receives independently reloaded producer artifact
bytes and exact causal lineage, never a workspace path or the expected assertion.
Fresh runtime, provider, host-write and authority admissions remain mandatory.
Tool-free proposals and controller writes are not a host filesystem sandbox.

Authenticated `queue show` / existing Queue HTTP readback adds optional typed
`graph_nodes`: exact admissions, pass caps, input lineage, node dispositions,
artifacts and receipts, independently of root success or failure. It exposes no
managed contract, private workspace, source bytes or credential values. Missing
admission/checkpoint remains missing; corrupt reads fail closed. Root fields keep
their historical meaning. Generic strict `loops validate FILE` / `loops publish
FILE` can carry a canonical v7 definition; no new managed builder command or
browser launch workflow is implied. Confirm installed capabilities separately.

Synthetic protocol and durable regressions do not qualify a real provider,
installed target, contribution delivery, or general multi-node scheduling.
See [the runtime handoff](MANAGED_PRODUCER_CONSUMER_RUNTIME_HANDOFF.md) for the
distinct live-provider acceptance boundary.

## Durable execution and remaining gates

`loop.NewManagedDoerRevision` seals v7 `managed_doer`: exact source type
`string` or `artifact`, required `source`, sole required artifact `result`,
mandatory expected text/digest, exact-byte policy, one writable path, no CODING,
and 1–2 implementation passes. Raw artifact verification is not the v5 JSON
selected-file envelope. Both nodes resolve before claim; each uses the existing
selected-file runner, durable cursor, normal ApplyDoerEdits and fresh admission.
One outer attempt cannot reset child budgets. Consumer admission requires the
exact successful producer checkpoint and receipt, not equal bytes alone.
Non-success child checkpoints retain typed denial/expiry/cancellation/failure.
Aggregate completion reloads both node records and content-addressed evidence.

Parent independently reports PASS for focused synthetic positive/negative managed
chain and durable-chain tests, including same-byte wrong causal identity,
corruption at runner admissions/evidence, cancellation/deadline/authority expiry,
revocation, host/pass-cap denial, lease expiry and concurrent duplicate processing.
Those are synthetic regressions, not live-provider proof. The app readback unit
test covers both node projections, absent admission and corrupt identity. Controlled
durable reopen through public `GetQueueItemAs` also covers successful and failed
roots. The debugger distinguishes this exact chain from unsupported definitions
and exposes actual optional node checkpoints without treating definition edges as
handoff evidence. Legacy root Doer failures retain `doer_loop_failed` for existing
continuation/requeue compatibility; new managed-node reason mapping stays scoped
to managed execution.
Fresh HTTP/installed-target acceptance, broad normal/race/vet/security checks and
independent repaired-candidate acceptance remain tester/parent work. No live authority
has been supplied/copied; no provider/model/config/grant changes are authorized.
Source implementation and synthetic evidence do not imply publication,
deployment, release, installation or live-provider qualification.
